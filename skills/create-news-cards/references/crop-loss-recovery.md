# 중간 카드 잘림 진단과 복구

## 먼저 잘린 위치를 구분한다

- 로컬 candidate PNG부터 제목·마지막 표 행이 없으면 생성/후처리 문제다. Instagram DOM이나 crop control을 고쳐 해결됐다고 보고하지 않는다.
- backend raw에도 없으면 생성 자체의 누락이다. raw에는 있고 candidate에서 사라졌으면 `cover` 변환 문제다.
- 로컬 PNG는 완전하지만 Instagram preview만 잘리면 게시 스킬의 `자르기 선택 → 4:5`를 확인한다. 이미 선택한 파일을 다시 업로드하지 않는다.

2026-09-05에는 요청 크기 1024×1536과 실제 원본이 달랐다. 중간 카드 일부는 실제 1024×1536이며 중앙 4:5 변환에서 위·아래 128px씩 제거돼 제목과 표 마지막 행이 사라졌다. 다른 후보는 916×1717로 생성돼 위·아래 286px씩 제거됐다. 최종 PNG가 1080×1350이라는 사실만으로 내용 보존을 판정할 수 없다.

## 실제 원본을 기준으로 검사한다

```powershell
python skills/create-news-cards/scripts/audit_generated_crops.py --work-dir <run>/03-create --direction <direction-id>
```

`crop-audit/<direction-id>/report.json`과 비교 JPEG를 확인한다. 왼쪽 raw의 녹색 사각형만 최종 crop에 남는다. 실제 raw 크기와 SHA-256, candidate SHA-256이 생성 manifest와 일치해야 한다. 진단은 원본/candidate 픽셀을 수정하지 않는다.

각 카드의 제목 전체, 본문, 사진의 핵심 인물/사물, 표 머리글과 마지막 행, 자료 장면 라벨, 날짜, 출처를 raw와 최종본에서 대조한다. raw에도 누락된 글자를 crop 탓으로 돌리지 않는다. `visual_review_required`는 성공 표시가 아니다. 여백 72px은 **최종 이미지 기준**이다.

1024×1536 raw의 중앙 4:5 영역은 `x=0..1024, y=128..1408`이다. 최종 72px 여백까지 고려하면 모든 글자·표 테두리는 raw `x=69..955, y=197..1339` 안에 있어야 한다. 실제 크기가 다르면 보고서의 사각형을 기준으로 다시 계산하며 이 숫자를 그대로 적용하지 않는다.

## 해당 카드만 복구한다

1. 실패 후보와 raw·manifest·job을 별도 repair 폴더에 보존한다. 완료된 검색·기획 hash를 조용히 바꾸지 않는다.
2. 같은 세트에서 내용·여백 QA를 통과한 4:5 결과를 마지막 레이아웃 reference로 쓰고, 해당 카드의 사실 reference는 첫 번째로 유지한다. 생성 후보 reference임을 기록하며 공개 기사 원본으로 위장하지 않는다.
3. 큰 제목과 사진 패널 높이를 줄여 **제목 + 줄글 + 사진 + 완전한 표 + 날짜** 전체를 생존 영역 안에 재배치하게 한다. 본문/표를 미세문자로 만들거나 일부 행을 없애지 않는다. 표 마지막 행의 exact 문구를 다시 명시한다.
4. 수정한 카드만 모델로 재생성한다. 텍스트 오버레이, 기존 crop 확대, 늘이기, 잘린 상태의 업로드로 해결하지 않는다.
5. 새 raw/최종본과 360px preview를 다시 검사한다. 성공 생성 응답만으로 교체본을 승인하지 않는다. 후보·생성 manifest·최종 slide의 hash를 연결한다.

raw는 정확하지만 crop-safe 재생성에서도 동일 손실만 반복될 경우에만 기존 스킬의 **1장 제한 contain 폴백**을 검수한다. 여러 중간 카드를 일괄 패딩해 덮지 않는다. 출처나 본문이 360px에서 작아지면 실패다. 모든 최종 카드가 통과한 뒤에만 `finalize_generated_set.py --visual-qa-passed`를 실행한다.
