# 뉴스픽 지금 보고

운영 폴더(이 저장소 루트, `output/`이 있는 곳)에서 아래 명령 하나로 보고를 만든다. 이 명령은 Instagram을 읽지 않는다. 로컬 기록(run·게시 대기열·팔로우/언팔 로그·팔로워 기록·ego 연결 기록)과 ego 공간 목록, Windows 예약 작업만 본다. 그래서 언제 불러도 계정에 부담이 없다.

```powershell
$env:PYTHONUTF8 = '1'
python skills/upload-news-pick/scripts/daily_report.py --status
```

Git Bash라면 `PYTHONUTF8=1 python skills/upload-news-pick/scripts/daily_report.py --status`.

## 보여 주는 방법

1. 출력 전체를 코드 블록(```)에 그대로 넣는다. 줄이거나 다시 쓰지 않는다. 사용자가 이 모양을 직접 골랐다(표가 아니라 짧은 목록).
2. 코드 블록 아래에는 확인이 필요한 줄만 한 줄씩 짚는다.
   - `❌`·`⚠️` 회차: `output/scheduler/editions/<날짜>-<HHMM>.json`의 `final_result.reason`과 그 run의 `04-publish/result.json`을 읽고 원인을 한 줄로 쓴다.
   - `예약 이상`: 결과 코드가 0이 아닌 작업은 `output/logs/scheduler/`의 해당 로그 끝부분을 보고, 꺼진 작업은 꺼져 있다고 쓴다. 스토리의 결과 코드 2는 대개 정규 3건이 다 공개 검증되지 않아 게시 전에 멈춘 것이다(`output/scheduler/daily-story/editions/`).
   - 회차가 통째로 건너뛰어졌으면 `AGENTS.md` 맨 위에 운영 중지 문구가 있는지 먼저 본다. 예약 실행은 그 문구를 따른다.
3. 보고 중에는 아무것도 고치거나 다시 실행하지 않는다. 고칠 일이 보이면 무엇을 할지 제안만 하고 사용자의 답을 기다린다.

## 읽는 법

- `✅ 게시 (06:30 시작 → 07:09 게시)`: 예약은 회차 30분 전에 준비를 시작하고, 공유는 회차 시각 뒤 1~15분 사이 무작위다. `*`가 붙은 시각은 공유 기록이 없어 공개 검증 시각으로 대신한 값이다.
- `· 수동 대체`: 정규 회차가 빠져서 수동 게시로 대신하고, 사용자 지시로 `output/scheduler/editions/<날짜>-<HHMM>.replacement.json`에 기록한 경우다. 19시 스토리도 이 게시를 그 회차로 센다.
- `ego: …`: 설정값이 아니라 게시 시각 직전에 게시 공간(`newspick-instagram`)이 실제로 붙어 있던 프로필이다(`output/logs/ego-sessions.jsonl`). 기록이 없으면 `기록 없음`. 정상은 `뉴스픽 (Profile 2)`다.
- `팔로워 … (11/12 기준)`: 지금 보고는 Instagram을 읽지 않으므로 오늘 팔로워 기록이 아직 없으면 마지막 기록을 날짜와 함께 보여 준다. 오늘 숫자는 19:30 일일 보고가 프로필 페이지를 한 번 읽어 남긴다.
- `ego 게시 공간: 지금 열린 공간 없음 · 마지막 연결 …`: 게시가 끝나면 게시용 공간이 닫히므로 낮에는 정상이다.

## 다른 날짜

지난 날짜를 물으면 `output/reports/daily/<YYYY-MM-DD>.txt`(그날 19:30 일일 보고)를 그대로 보여 준다. 이 파일을 다시 만들려고 `--status` 없이 스크립트를 돌리면 그날 보고 파일을 덮어쓰므로, 사용자가 원할 때만 한다.
